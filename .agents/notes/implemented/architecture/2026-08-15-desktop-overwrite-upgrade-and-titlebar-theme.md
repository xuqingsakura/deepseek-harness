# Agent Note: Desktop overwrite-in-place upgrades, auto-update, and title-bar theme

Status: implemented

English | [中文](2026-08-15-desktop-overwrite-upgrade-and-titlebar-theme.zh.md)

## Problem

Two desktop-shell defects blocked the update workflow:

- **Every NSIS reinstall failed with "Failed to uninstall old application files...:2".** electron-builder >= 26.7 (regression electron-userland/electron-builder#9593) runs the previous uninstaller with `--updated` before reinstalling; that path atomically renames `$INSTDIR` aside and aborts with exit code 2 when any file is locked. Updates therefore required uninstall-then-install, losing shortcuts and risking the user's data-dir confusion.
- **The title-bar whale stayed black in dark mode.** The injected favicon SVG colored itself through `@media (prefers-color-scheme: dark)`, which tracks the OS/browser scheme — but the app's light/dark palette is `--dsw-*` token-driven (the theme presenter writes root `color-scheme` plus body tokens). The two were not reliably in sync, so the whale did not turn white like the sidebar FishLogo below it.

## Decision

- **Overwrite-in-place upgrades.** `apps/desktop/build/installer.nsh` (electron-builder custom NSIS include, auto-included from `buildResources`) deletes the `UninstallString`/`QuietUninstallString` values of the uninstall registry key in both HKCU/HKLM and both 32/64-bit views inside `customInit` (`.onInit`). `uninstallOldVersion` then finds no previous install, skips the old uninstaller, and the new package overwrites the old files in place; `registryAddInstallInfo` re-creates the uninstall entry right after. `nsis.perMachine: true` keeps every install in one scope (`C:\Program Files\DeepSeek Harness`) so a later Setup.exe overwrites the earlier one instead of stacking scopes.
- **Auto-update.** `electron-updater` is wired into the main process: the feed URL resolves from `DSH_UPDATE_FEED_URL`, else `%APPDATA%\dsh-desktop\update-config.json` (`{"url": "..."}`), else the packaged `app-update.yml` placeholder. The tray gains a "检查更新" item for manual checks; a startup check runs silently after 12 s only when a feed is configured (never "no update" noise); `update-downloaded` posts a notification whose click calls `quitAndInstall()`.
- **Title-bar whale follows the app theme.** The preload paints the favicon with `#dsh-titlebar-icon path { fill: currentColor }`, inheriting the title bar's `color: var(--dsw-alias-label-primary, #111418)` — the same token the sidebar FishLogo consumes, so the whale is dark ink in light mode and near-white in dark mode, with no IPC and no OS-scheme dependency.

## Alternatives considered

- **Patch the old uninstaller's `--updated` atomic rename** — impossible: the uninstaller is generated by electron-builder; the custom-include registry deletion is the documented community workaround for #9593.
- **Set `nativeTheme.themeSource` in the main process** — would require the renderer to push every theme switch over IPC and still diverges from the token palette semantics (custom themes / overrides).
- **Keep `prefers-color-scheme` in the SVG** — the app palette is token-driven; the OS scheme is orthogonal and does not flip on in-app theme changes.

## Consequences

- Reinstall and version upgrades no longer need uninstall-first: verified with a silent rc.8-over-rc.8 reinstall exiting 0 with no dialog; a cross-version rc.9-over-rc.8 install follows the same code path.
- The uninstall registry entry is momentarily absent between `customInit` and `registryAddInstallInfo`; a cancelled install could orphan the old files (rare — the next install overwrites them, and Windows "Apps" regains the entry on completion).
- Auto-update needs a real feed URL (env var or `update-config.json`); the packaged placeholder URL stays inert until a release channel exists.
- The smoke run asserts the dark-mode whale fill through a simulated presenter apply (`DESKTOP_TITLEBAR_DARK`), so a future regression fails CI-style in the desktop self-check.
