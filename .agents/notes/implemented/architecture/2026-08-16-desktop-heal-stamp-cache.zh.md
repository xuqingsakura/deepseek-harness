# Agent Note：画像模块回退修复带印章缓存，热启动跳过

Status: implemented

[English](2026-08-16-desktop-heal-stamp-cache.md) | 中文

## 问题

每次启动都会执行 `healProfilesModuleFallback`：对安装的整个依赖闭包做 BFS（逐个读 package.json），并对每个已链接包做符号链接校验。桌面端每次 启动在窗口出现前都要做数千次文件系统调用。

## 决策

成功修复后在 `profiles/node_modules/.dsh-heal-stamp` 写入印章文件。印章 内容是安装锚点路径加安装清单直接依赖/对等依赖集合的 SHA-256。热启动时印章 匹配则直接返回（实测快约 40 倍：画像组合 638ms → 15ms）；路径变化 （重装/迁移）或直接依赖变化会使印章失效并重新修复。传递依赖的单独变化不 跟踪——桌面端随包闭包在安装间不可变，链接不会漂移。

## 影响

冷启动仍会修复并写印章；热启动跳过闭包遍历。权衡记录在签名辅助函数中： 修复后若链接被删除，在签名变化前不会修复（对不可变的桌面闭包可接受； CLI 用户可删除印章强制重新修复）。

## 备选方案考量

- **每次启动都重新修复** —— 打戳之前的行为；构造上正确，但每次启动都要做完整闭包 BFS 与逐链接 junction 校验（仅画像组合即实测 638ms）。被否决：桌面闭包在两次安装之间不可变，热启动跳过不会漂移。
- **只对安装路径打戳** —— 更便宜，但就地升级导致清单直接依赖集变化时无法失效。被否决：仅路径的戳可能在需要修复的变更安装后仍跳过。
